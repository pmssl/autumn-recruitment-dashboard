# 0002：可选的本地按钮点击计数

- **日期**：2026-11-06（Asia/Shanghai）
- **状态**：当前源码已实现；本地构建和交付结果以本任务验证记录为准，尚未发布。
- **来源**：用户要求统计各页面按钮的生效点击次数，保存在本地，并分别提供有统计和无统计的 EXE。

## 决定

使用 Cargo `click-stats` feature 从同一原生源码构建两个 Windows EXE。统计版由 `native/src/main.rs` 在按钮操作生效后调用 `native/src/click_stats.rs`，将累计计数写入程序数据目录的 `click-stats.json`。普通版使用同一回调代码，但计数器在编译时为空实现，不读取或写入统计文件。投递数据仍由 `Store` 独立保存在 `applications.json`。

## 考虑的方案与原因

- 两份独立源码：容易使界面与业务行为分叉，不采用。
- 单一 EXE 的运行时开关：能关闭计数，但用户明确需要两个可直接区分的 EXE，不采用。
- 将计数混入 `applications.json`：会改变投递数据模型并增加与业务保存的耦合，不采用。

## 影响与边界

统计文件是本地累计值，以中文操作名称为键；不记录逐次点击时间或投递内容。页面与筛选重复选择、失败保存、无效日期不会增加对应计数。输入框输入、自动刷新和本机 API 不属于按钮点击。两个 EXE 若放在同一目录，使用同一 `data/`，仍受现有单实例目录锁约束。统计文件损坏时拒绝覆盖原文件。证据：`native/Cargo.toml`、`native/src/main.rs`、`native/src/click_stats.rs`、`native/ui/app.slint`。
